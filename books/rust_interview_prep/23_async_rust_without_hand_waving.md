# Async Rust Without Hand-Waving

Async Rust has a reputation for being difficult.
I think that reputation is fair.
I also think it is manageable once you stop treating it as magic.

`async fn` returns a future.
That future is lazy until polled.
`await` marks a suspension point where control may return to the runtime.
Those three facts carry most interview discussions.

Where candidates struggle is implicit state.
An async function is a state machine generated by the compiler.
Captured values, borrow scopes, and lifetimes interact with that machine.
If boundaries are messy, compiler diagnostics become theatre.

My practical rules are conservative:
- keep async functions small and purpose-specific;
- avoid holding locks across `.await`;
- prefer owned data at async boundaries where borrow complexity explodes;
- make cancellation effects explicit in design.

That last one matters.
If a task is cancelled midway, what state had already changed?
If the answer is unclear, retries may corrupt assumptions.

Interviewers often ask about pinning.
I respond proportionally.
Most everyday async code does not require manual pin choreography.
But I understand the concept: some futures are self-referential and must not move once pinned.
No drama, just model clarity.

A common failure pattern is “async everywhere” by reflex.
I’m not convinced.
Synchronous code is often clearer for CPU-bound local logic.
Async is for concurrency around waiting, not a fashion statement.

If the panel asks for debugging strategy, I give one:
- reproduce with controlled load;
- add timing and queue-depth instrumentation;
- isolate slow awaits and lock overlap;
- validate improvements against p95/p99, not anecdotes.

This chapter connects naturally to [Tokio Execution Model, Plainly](./22_tokio_execution_model_plainly.md).
Runtime model explains scheduling.
Async discipline explains how your code behaves inside that schedule.

Good async Rust is not about clever syntax.
It is about bounded work, explicit control flow, and predictable cancellation behaviour.
That is what production rewards.
